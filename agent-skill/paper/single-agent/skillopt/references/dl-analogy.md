# 深度学习 ↔ SkillOpt 概念类比

> 原始资料：[Deep Learning ↔ SkillOpt Analogy](https://github.com/microsoft/SkillOpt/blob/79124b37e9a6371e13b753f8bcd7adb1e493ade1/docs/guide/dl-analogy.md)
> 本文为已存档官方文档的中文翻译；代码标识、参数名和数值保持原样。

SkillOpt 的设计基于一个核心认识：**优化自然语言提示词，与训练神经网络具有相同的结构**。本文将深度学习中的各个概念与 SkillOpt 中的对应机制逐一对照。

## 完整映射

| 深度学习 | SkillOpt | 说明 |
|---|---|---|
| **模型权重** | Skill 文档（Markdown） | 被优化的对象 |
| **前向传播** | 轨迹执行（Rollout） | 目标模型使用当前技能执行任务 |
| **损失函数** | 任务评估器 | 对任务执行质量评分 |
| **反向传播** | 反思（Reflect） | 优化器分析失败情况，生成编辑补丁 |
| **梯度** | 编辑补丁 | 对技能提出的修改建议 |
| **梯度聚合** | 补丁聚合 | 合并相似编辑 |
| **梯度裁剪** | 编辑筛选 | 限制每一步的最大编辑数量 |
| **学习率** | `learning_rate` | 每一步最多应用的编辑数量 |
| **学习率调度器** | `lr_scheduler` | 编辑预算调度：余弦、线性、恒定或自主调度 |
| **随机梯度下降（SGD）更新** | 技能更新 | 将筛选出的补丁应用到文档 |
| **验证集** | 筛选数据划分（Selection split） | 门控在接受更新前检查是否有改进 |
| **训练步** | Step | 一次“轨迹执行 → 反思 → 更新”循环 |
| **训练轮次** | Epoch | 一轮完整执行，包含慢更新和元记忆 |
| **动量** | 慢更新 | 在轮次边界进行跨时间比较 |
| **元学习** | 元技能 | 跨轮次保留优化器策略记忆 |
| **批大小** | `batch_size` | 每次轨迹执行采样的任务数量 |
| **数据并行** | `analyst_workers` | 并行反思工作单元 |
| **训练集** | 训练数据划分 | 用于轨迹执行的样本 |
| **测试集** | 测试数据划分 | 留出数据，用于最终评估 |
| **预热** | 隐式实现 | 早期较高的学习率支持广泛探索 |
| **检查点保存** | 技能快照 | 每个被接受的更新步之后保存 |
| **迁移学习** | 种子技能／跨基准初始化 | 从预训练技能开始 |

## 这种类比为什么有用

1. **熟悉的理解框架**：机器学习从业者能够快速理解如何调优 SkillOpt。
2. **有依据的超参数搜索**：对 `learning_rate` × `lr_scheduler` 进行网格搜索，与深度学习中的做法相同。
3. **可复用的机制**：门控提供基于验证的模型选择，慢更新则在不同轮次之间发挥类似动量的作用。

门控会对每个候选更新单独作出接受或拒绝决定。SkillOpt 没有实现门控耐心计数器，也不会因为连续拒绝若干候选更新就停止训练。

## 超参数迁移规则

根据我们的实验，下列深度学习直觉可以较好地迁移：

!!! success "可以迁移的经验"
    - **余弦调度优于恒定调度**：与深度学习一样，余弦退火有助于收敛。
    - **适中的学习率（4–16）优于过高或过低的学习率**：编辑太少会导致学习缓慢，太多则会引入噪声。
    - **慢更新有帮助**：跨时间比较有助于防止跨轮次的灾难性遗忘。
    - **元技能记忆能改善反思**：优化器可从跨轮次的策略笔记中获益。

!!! warning "不能直接迁移的经验"
    - **批大小更大不等于效果更好**：考虑 API 成本后，扩大轨迹执行批次的收益会递减。
    - **轮次更多不等于效果更好**：技能的收敛速度快于神经网络，通常 2–4 轮就足够。
