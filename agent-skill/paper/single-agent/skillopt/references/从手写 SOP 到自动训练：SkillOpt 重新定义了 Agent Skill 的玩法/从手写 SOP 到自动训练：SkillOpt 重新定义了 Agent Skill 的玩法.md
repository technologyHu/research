微软研究院近期放出的一篇论文，正在重新定义行业对 Agent Skill 的认知。

一句话讲透核心：我们一直当作「提示词补充」的 Skill 文档，本质上可以像神经网络的权重参数一样，被纳入一套完整、可控的训练循环。

这项来自 Microsoft Research 的工作名为 **SkillOpt**，思路直白却极具颠覆性：它不去微调模型的内部参数，而是把 Agent 所依赖的 Skill 文本作为唯一可训练的外部状态，参照深度学习的训练范式，通过执行、反思、编辑、验证的闭环，实现 Skill 的自动化迭代优化。

实验结果相当亮眼。

在 6 项基准测试、7 个目标模型、3 种执行环境的组合下，SkillOpt 在全部 52 个测试单元中均取得最优或并列最优成绩。在 GPT-5.5 直连对话场景下，任务平均分提升 23.5 分；接入 Codex 代理执行环后，平均提升达 24.8 分；即便是在 Claude Code 环境中，也能带来 19.1 分的平均涨幅。

更值得关注的是，它不仅大幅优于无 Skill 的基线表现，也全面超越了人类手写 Skill、大模型一次性生成 Skill，以及 Trace2Skill、TextGrad、GEPA、EvoSkill 等多种现有自动优化方案。

当下 Agent 开发的通用做法，是为模型配套各类执行说明文档。

Claude Code 依赖 CLAUDE.md 定义行为，Codex 通过 Agents.md 规范流程，各类 Agent 框架也都有自己的 Skill 文档、最佳实践、系统约束与执行规程。

从业者的普遍思路是：花费数小时反复打磨一份规则说明，期望以此提升 Agent 在同类任务中的稳定性与表现。

但这种方式高度依赖编写者的经验，最终效果存在很强不确定性 —— 你自认规则已经写得足够周全，却往往存在各种隐患：遗漏了关键执行约束、写下的泛化建议缺乏可操作性、加入了看似合理实则会误导模型的描述，甚至没人知道一份「最优 Skill」到底该是什么样。

针对这个痛点，微软的解决方案非常直接：既然人工编写难以实现 Skill 的全局最优，那就交由 AI 自主完成这份文档的训练迭代。

**一**

**Skill，也可以像「权重」一样训练**

SkillOpt 最精妙的设计，是把深度学习的训练范式完整迁移到了文本空间。

在经典神经网络训练中，我们会执行前向传播、梯度计算、权重更新、学习率控制、验证集筛选最优 checkpoint；而在 SkillOpt 的框架里，这套逻辑有了精准的文本空间对应：

* **前向传播 → 任务滚动执行（rollout）**
* **梯度计算 → 轨迹反思复盘（reflection）**
* **权重更新 → Skill 文本编辑（edit）**
* **学习率 → 文本编辑预算（textual learning rate）**
* **验证集 checkpoint → 验证门禁机制（validation gating）**

通俗来讲，整个流程分为四步：先让 Agent 搭载当前版本的 Skill 执行一批任务，记录表现得分；再由独立的优化器模型分析成功与失败样本，定位问题根源；接着对 Skill 文档执行增、删、改操作；最后将修改后的版本放回验证集复测，只有确认性能提升，才会正式采纳这次更新。

这套机制带来的核心变化是：Skill 不再是一份凭经验撰写的静态提示词附件，而是成为了可训练、可验证、可迭代、可跨场景复用的标准化能力资产。

**二**

**双模型分工：执行端不动，优化端专职迭代**

SkillOpt 采用双模型架构，二者各司其职：

* **目标模型（target model）**：实际承担任务执行的模型，比如 GPT-5.5、Claude、Qwen 等
* **优化器模型（optimizer model）**：负责复盘目标模型的表现、分析错误模式、提出编辑方案的专用模型

你可以把它理解为「执行端 + 教练端」的配合：前者负责落地执行，后者专注于复盘优化、更新操作规范。

这套设计的工程价值很高：优化器模型仅参与训练过程，正式部署时完全不需要额外调用。训练结束后，最终交付的只是一份优化完成的 Skill 文档 `best_skill.md`，运行时不会产生任何额外的推理开销。

这和企业里的顾问模式异曲同工：前期投入成本，请专业团队打磨出标准化 SOP；后续大规模落地时，所有执行端直接按手册操作即可。

**三**

**受控更新：不是随便重写，而是像训练系统一样稳定迭代**

微软团队并没有让模型每轮都全盘重写 Skill 文档，而是加入了大量类似机器学习训练的「稳定器」机制，保障优化过程可控收敛。

其中最核心的稳定机制，是**文本学习率（textual learning rate）**。

论文中的默认配置为：单轮迭代最多允许执行 4 条规则级别的编辑。这个限制看似保守，却是优化过程稳定收敛的关键。

如果单轮修改幅度过大，有效修改和无效修改会相互混杂，验证集无法精准定位生效的规则，最终导致 Skill 表现来回震荡，前期沉淀的有效规则也可能被大幅改写直接覆盖。实验数据显示，取消编辑预算限制的版本，性能比默认 L\_t=4 的配置低 2-3 分，和深度学习中学习率过大导致训练震荡、无法收敛的现象完全一致。

除了编辑步长约束，SkillOpt 还有两项核心稳定机制。

第一项是**被拒编辑缓冲区（rejected-edit buffer）**。被验证集驳回的修改不会直接丢弃，而是会作为负反馈被记录下来，指导后续优化避开同类无效方向，避免重复踩坑。

第二项是**慢更新 / 元更新（slow/meta update）**，作用类似深度学习中的动量机制。每轮训练周期结束时，优化器会从更长的时间维度复盘前后阶段的 Skill 演化规律，执行一次节奏更慢、稳定性更高的全局更新，不会被短期的局部编辑冲抵。

这项机制的增益效果非常显著：移除 slow/meta update 后，SpreadsheetBench 基准的得分从 77.5 直接跌至 55.0，降幅达 22.5 分。

一言以蔽之：SkillOpt 的本质不是让 AI 随意改写文档，而是将 Skill 文本纳入了一套严格受控、可复现的训练闭环。

**四**

**性能表现：全场景霸榜，提升幅度远超小修小补**

论文覆盖了 6 项主流基准测试，任务类型跨度极大：

* SearchQA：搜索问答
* SpreadsheetBench：表格自动化
* OfficeQA：办公文档处理
* DocVQA：文档视觉问答
* LiveMathematicianBench：数学推理
* ALFWorld：具身环境多步交互

先看 GPT-5.5 直连对话场景的提升幅度：

**SearchQA：**从 77.7 分提升至 87.3 分，涨幅 + 9.6  
**SpreadsheetBench：**从 41.8 分提升至 80.7 分，涨幅 + 38.9  
**OfficeQA：**从 33.1 分提升至 72.1 分，涨幅 + 39.0  
**DocVQA：**从 78.8 分提升至 91.2 分，涨幅 + 12.4  
**LiveMath：**从 37.6 分提升至 66.9 分，涨幅 + 29.3  
**ALFWorld：**从 83.6 分提升至 95.5 分，涨幅 + 11.9

整体平均涨幅达 23.5 分。

其中表格与办公场景的提升最为突出，接近 39 分的涨幅意味着能力实现了质的跨越 —— 从「勉强可用、稳定性不足」，直接进入「可落地、可承载高强度任务」的区间。

更具价值的是它的环境通用性：在 Codex 代理执行环境中平均提升 24.8 分，在 Claude Code 环境中也有 19.1 分的平均涨幅。这说明它优化的不是特定聊天界面下的提示词技巧，而是更底层的任务执行策略与流程规范。

**五**

**超越人类手写：人工打磨的上限，败给了系统迭代**

这部分实验结果最具冲击力。研究团队将人类精心编写的 Skill 纳入对比基线，这些手写 Skill 长度在 145-516 tokens 之间，并非随手写就的草稿，而是经过打磨的成熟版本。

最终结果显示，SkillOpt 在 GPT-5.5 直聊场景下平均得分 82.3；即便把所有基线方法中每个基准的最优结果拼接起来，组合平均分也仅为 76.9。换言之，即便为每个任务单独挑选最优的人工或自动化方案，组合起来的表现依然不及 SkillOpt。

参与对比的方案涵盖了人类手写 Skill、大模型一次性生成 Skill、Trace2Skill、TextGrad、GEPA、EvoSkill 等主流方案，最终全部弱于 SkillOpt。

**六**

**学到了什么：沉淀出人类想不到的精细化执行规则**

论文最有启发性的不是分数，而是最终迭代出的 Skill 规则。这些规则有一个共性：看完你会觉得「理应如此」，但如果让人事先手写，绝大多数人都不会想到。

比如 SearchQA 任务迭代出的核心规则：根据问题线索的措辞推断答案类型，再从共现证据中选取最短、最规范的实体名称。这其实是在补一个非常细节却关键的认知：光找到正确答案还不够，还要匹配评测标准认可的输出形式。

SpreadsheetBench 沉淀的规则更具工程价值：先检查工作簿结构与公式逻辑，再将计算结果写入为静态值，而非依赖 Excel 自动重算。这精准命中了 Agent 处理表格的常见痛点：写入公式后默认环境会自动计算，但在自动化执行场景中，这一步往往不稳定，甚至直接导致任务失败。

ALFWorld 任务中学到的规则更像具身智能的操作手册：维护带视野感知的已访问 / 前沿位置列表；同类搜索连续失败时立即切换方向；拿到目标物品前不要反复返回目的地。本质上，它自主学会了「避免无效重复操作」的执行纪律。

这些规则的共性非常清晰：内容高度具体，没有「认真检查」「仔细思考」这类空泛表述；强流程化，明确操作步骤与执行规范；往往反常识，都是人类不会主动写入的细节；篇幅紧凑，但信息密度极高。

**七**

**演化过程：好Skill不是想出来的，是从失败里跑出来的**

论文还完整呈现了 Skill 的演化路径，能清晰看到一份初始普通的 Skill 文档，如何通过多轮执行与复盘逐步迭代到最终的成熟版本。

以 ALFWorld 为例，初始版本只是非常笼统的操作指引，比如「先寻找目标物品、再执行操作、最后放到指定位置」。第一轮执行后发现 Agent 频繁在房间内绕圈、重复搜索同一位置，系统便新增了「记录已访问位置、避免重复检索」的规则；继续迭代后又发现 Agent 拿到物品后会执行多余动作、破坏任务状态，于是补充了「获取目标后锁定当前进度」的策略；后续逐步补上循环检测、名称精确匹配、搜索方向切换等规则。最终任务得分从 49.3 提升至 74.6，涨幅达 25.3 分。

SpreadsheetBench 的演化路径同理：最初只是普通的「表格处理说明」，经过数轮迭代后，Skill 中沉淀出大量工程化规则：先检查工作簿的表头与数据范围、统一键值格式、用静态计算结果替代公式依赖、保留辅助计算列、对目标范围做整批写入而非局部修补。最终得分从 40.4 提升至 78.9，涨幅达 38.5 分。

这背后的核心逻辑很明确：优质的 Skill 从来不是凭空构思出来的，而是从大量真实失败样本中迭代、训练出来的。

**八**

**迁移能力：一次训练，多场景复用的文本资产**

SkillOpt 另一项极具实用价值的特性，是训练出的 Skill 具备优秀的跨场景迁移能力，并非只能在原始训练环境中生效。

论文完成了三类迁移验证：

* **跨模型迁移：**基于 GPT-5.4 训练的 SpreadsheetBench Skill，迁移到 GPT-5.4-mini 后仍能带来 + 9.4 的提升
* **跨执行环境迁移：**在 Codex 中优化的 SpreadsheetBench Skill，迁移到 Claude Code 后直接带来 + 59.7 的涨幅
* **跨任务迁移：**在 OlympiadBench 上训练的 Skill，迁移到相近的 Omni-MATH 任务，仍有 + 3.7 的提升

这个结论的产业价值很高：一次离线训练投入产出的不是单次有效的提示词，而是可迁移的文本能力资产。更换模型、执行环境，甚至相近的任务场景，优化后的 Skill 往往依然能发挥作用，真正成为可沉淀、可积累、可复用的知识资产。

**九**

**训练成本：一次性投入，长期持续兑现收益**

论文披露的训练成本也值得参考。对于 SearchQA、DocVQA 这类流程型基准，测试得分每提升 1 分，约消耗 0.6M-3.6M 训练 token；对于 SpreadsheetBench、ALFWorld 这类多步复杂轨迹任务，每提升 1 分约消耗 37.9M-46.4M token。

单看数值似乎不低，但核心在于：这是一次性投入。Skill 训练完成后，部署阶段不需要再调用优化器模型，性能增益会在每一次任务执行中持续兑现。对于高频执行的 Agent 场景，训练成本会被快速摊薄。

**十**

**行业启示：Skill将从手工制品，走向体系化训练**

这篇论文最大的价值，不在于某个基准涨了多少分，而在于它提供了一种全新的认知：Skill 文档不该是「写一次就完事」的手工制品，而应该成为「持续训练、持续验证、持续迭代」的优化对象。

过去行业的普遍认知是：模型是核心，提示词是辅助，Skill 文档只是工程衔接的胶水。SkillOpt 彻底扭转了这个逻辑：在闭源模型的场景下，开发者无法修改模型参数，真正可控且性价比最高的优化对象，就是外部的 Skill 文本状态。而这份状态不该凭经验维护，应该用训练权重的严谨范式去迭代优化。

这套核心循环也完全可以被人工复刻落地：让 Agent 在真实任务中运行、沉淀失败样本、归纳错误模式、针对性补充规则、通过验证集评估效果、只保留确有增益的修改。归根结底，这篇论文传递的核心观点是：手写 Skill 可以是起点，但绝对不该是终点。
