# Claude Mods 术语速查

这份速查配合 [调研报告](report.md) 阅读。正文在概念第一次出现时解释含义，并提供执行过程或例子；这里用于读到一半时快速回查。英文名、代码标识与章节号保留，方便对照源码。例子帮助理解机制，不是新增的真实宿主运行记录。

## 运行系统与扩展

| 名称 | 怎样理解 | 对应正文 |
| --- | --- | --- |
| Host / 宿主 | Claude Code 本体，负责智能体运行、工具执行和界面显示；mod 接入它提供的接口 | 1、2.1 |
| 智能体（Agent） | 在模型建议与实际操作之间反复推进任务的执行者；子智能体负责被另行派出的任务 | 1、5.5 |
| 主智能体 | 负责当前用户任务、调用模型与工具并推进执行的智能体 | 1、5.5 |
| 子智能体 | 由主智能体启动、承担分工任务的智能体（Subagent） | 5.5 |
| Harness | 围绕模型的运行系统，包括上下文、工具、权限、任务推进和 UI | 1、9.6 |
| Plugin / 插件 | 包含元数据、配置和代码的安装与分发单位 | 1.2、2.2 |
| Mod | plugin 中通过函数处理器定制事件行为或界面的扩展能力 | 1.2 |
| Hook / 挂接点 | 宿主在某个节点调用扩展代码；传统脚本 hook 和函数 hook 的接入方式不同 | 1.2、3 |
| Hooks module | 注册函数处理器的代码模块，通常导出 register | 2.2 |
| Manifest | 插件的说明文件，记录名称、版本等元数据及相关配置 | 2.2 |
| Skill | 向模型提供任务方法和知识的内容 | 1.2 |
| MCP | Model Context Protocol，模型应用连接外部工具和服务的协议 | 1.2 |
| API / 能力接口 | 宿主允许扩展调用的一组方法，如读取文件、绘制界面 | 2、3.1 |
| Namespace / 命名空间 | 一组相关方法的名字，如 $.fs 是文件操作、$.ui 是界面操作 | 2.3.1 |
| Contract / 契约 | 接口双方约定的参数、返回值、可用行为和失败处理规则 | 1.5 |
| CLI / 命令行界面 | 在终端中通过命令使用程序；报告中的本机 CLI 指已安装的 Claude Code 命令 | 附录 A.4 |
| SDK / 开发工具包 | 供其他程序调用的接口与工具；拥有 SDK 入口不代表具有相同 UI | 5.3 |

## 代码加载与运行边界

| 名称 | 怎样理解 | 对应正文 |
| --- | --- | --- |
| Static scan / 静态扫描 | 在代码运行前读取源码，识别注册事件和宿主调用等信息 | 2.3 |
| Literal / 字面量 | 在源码中直接写出的值，如 on('tool.call', ...) 中的事件名 | 2.3.1 |
| Matcher / 筛选条件 | 限定 handler 处理哪些事件输入，如只处理工具名为 Bash 的调用 | 2.3.1 |
| Schema | 对字段格式、类型和允许取值的约束 | 2.3 |
| AST / 抽象语法树 | 把代码语法表示成结构化树，方便程序检查和转换；宿主使用哪种解析器未公开 | 2.3.2 |
| .d.ts / 类型声明 | 描述 TypeScript 接口的文件；它本身不执行操作，也不自动创建方法 | 2.3.2、6.5.1 |
| Frozen / 冻结输入 | 输入及嵌套字段按只读对待；改变事件时创建副本 | 2.3.2、3.1 |
| Worker / 工作线程 | 执行扩展代码的一侧；当前说明中已安装 mods 共用 hooks worker | 2.4 |
| RPC | 把请求送到另一运行环境，再收回结果；具体宿主消息协议未完整公开 | 2.4 |
| MessagePort | 收发消息的端点，帮助解释 Worker 与宿主之间的消息来源 | 2.4 |
| Structured clone | 复制可传输的数据结构，不能当成任意函数或 DOM 对象都能搬运 | 2.4 |
| Side effect / 副作用 | 会影响外部世界的操作，例如写文件、启动程序、发送请求 | 2.4 |
| Sandbox / 沙箱 | 限制代码可访问资源的环境；缺少 Node/DOM 不自动证明 OS 权限被缩减 | 2.4.2、4.3 |
| Node / DOM / OS | Node 是 JavaScript 运行环境；DOM 是浏览器的网页对象树；OS 是操作系统。三者处在不同层级 | 2.4.2 |
| Origin / 发起来源 | next.origin 记录谁发起本次事件，由宿主设置 | 2.4.1 |
| Provider / 提供者 | 部分事件中的 e.provider 指提供工具或命令的一方，未必是调用方 | 2.4.1 |

## 事件链与控制流

| 名称 | 怎样理解 | 对应正文 |
| --- | --- | --- |
| Event / 事件 | 宿主触发的一项待处理行为或生命周期节点，如工具调用、回合完成 | 1、3.2 |
| Handler / 处理器 | 接收事件并返回结果的函数，常见参数为 ($, e, next) | 3.1 |
| Middleware / 中间件 | 参与一次操作前后过程的处理器，可以继续、改写或接管 | 3.3 |
| Dispatch / 分派 | 找到本次事件应进入的处理链，并按规则执行 | 2.1、3.6 |
| Continuation / 后续计算 | 把“当前步骤之后要做什么”封装成可调用函数；这里主要指 next | 3.1、3.6 |
| next(e) | 正常继续当前事件的剩余链；返回后当前 handler 还可以处理结果 | 3.5 |
| next.to(e, tier) | 获准的处理器跳过部分下游层，从指定层继续；不改变发起来源 | 3.5 |
| Tier / 层级 | 按来源与管理角色分组的处理层，如 prepend、user、append、builtin、core | 3.4 |
| Guard | 做保护检查的处理器，例如复核受保护权限决定 | 3.4、6.6 |
| Managed | 由组织管理的配置、指令或扩展；其约束不能简单视为用户偏好 | 3.4、4.4 |
| Short-circuit / 短路 | 当前层直接返回，后面的链不再沿这条路径运行 | 3.3 |
| Trace / 过程记录 | 最新一次 next 下游执行经过了哪些层、如何输入输出、是否失败或跳过 | 3.6.3 |
| Re-entry / 重入 | handler 尚未结束，其 API 操作又发起事件处理；活跃 hook 的保护用于避免直接递归 | 3.7 |
| Active frame / 活跃调用帧 | 当前仍未结束的一次函数调用；保护该帧不等于跳过整个插件 | 3.7 |
| Lent | 当前参考用于标识涉及另一个 mod 所提供能力方法的情形 | 3.7 |
| .catch / 恢复处理器 | 本报告主要指 hook 注册的失败恢复契约；不能与任意 try/catch 混同 | 3.6.2、3.9 |
| Session / Turn / Step | 会话、其中一次回合、回合中的模型请求步骤；一回合可以包含多次请求与工具执行 | 3.2 |
| Fail-open / Fail-closed | 检查失败后继续，或检查失败后阻止继续；门禁需要明确自己的错误策略 | 3.9 |
| Self-time / 自身执行时间 | 按预算规则计入当前处理器的时间，多数 API/next 等待排除在外 | 3.9 |
| Wall-clock / 墙钟时间 | 用户从开始到结束实际等待的时间，包含外部与下游等待 | 3.9 |
| Rollback / 回滚 | 撤销已发生的改变；收到取消信号本身并不自动做到这一点 | 3.9、4.2 |

**两个容易混淆的判断：** trace 的 rejected 描述执行链以异常拒绝结束，工具判定的 deny 描述权限或结果拒绝，二者不能直接等同。普通代码再次调用 next 可能重复执行；失败恢复中取回已有结果则是限定场景的特殊语义。

## 能力构造与流式输出

| 名称 | 怎样理解 | 对应正文 |
| --- | --- | --- |
| engine.create | 参与建立 $ 能力表的事件，先取得内层接口，再按契约组合或限制 | 2.5 |
| Fold | 逐层把已有结果组合成新的结果；这里主要观察能力表由内向外返回的顺序 | 2.5 |
| Descriptor | 描述有哪些能力方法、怎样调用的接口数据；完整宿主编译与传输机制未公开 | 2.5.1 |
| Declaration merging / 声明合并 | TypeScript 合并多份同名接口声明，用于补类型，不会自己产生运行时方法 | 5.4.2、6.5.1 |
| Promise | 一次尚未完成或已经完成的异步任务，可能成功也可能失败 | 3.8、6.6.1 |
| TTL | 缓存的有效时长；政策 helper 的窗口从读取开始时刻计时 | 6.6.1 |
| Chunk | 流式执行过程中的一块输出内容 | 3.8 |
| Async generator / 异步生成器 | 可以等待并逐次产生输出、最后结束的 JavaScript 函数形式 | 3.8 |
| Iterator / 迭代器 | 提供逐次读取流内容和结束状态的对象 | 3.8 |
| yield* | 转发下游产生的内容，并在下游结束时取得最终返回值 | 3.8 |
| for await | 遍历异步流的输出块；循环变量不会自动接到生成器的最终 return 值 | 3.8 |
| Backpressure / 背压 | 接收方处理较慢时，让发送方放慢，避免无限积压；不能只由生成器写法证明宿主全链路行为 | 3.8 |

## 界面、状态与异步结果

| 名称 | 怎样理解 | 对应正文 |
| --- | --- | --- |
| Declarative UI / 声明式界面 | 代码描述要显示的内容与结构，宿主负责把它画出来 | 5.1 |
| Element tree / 元素树 | 容器和子元素的嵌套关系，例如 Box 内有 Text 和 Button | 5.1 |
| Surface | 终端或桌面等显示环境，各自支持不同元素和交互 | 5.1、5.3 |
| Component / 组件 | 一块可绘制的界面位置或内容，如 AbovePrompt、Pane | 5.1、5.2 |
| Props | 传给组件的参数，例如待显示的数据、尺寸 | 5.2 |
| Callback / 回调 | 操作发生后执行的函数，例如按钮 onPress | 5.2.1 |
| Closure / 闭包 | 函数还能访问创建时环境中的变量，适合记住按钮对应哪项请求 | 5.2.1 |
| Handle / 句柄 | 帮助宿主找到交互元素或对应回调的标识，实际格式未公开 | 5.2.1 |
| Client | 运行在显示一侧、处理频繁输入和局部重绘的模块 | 5.2.3 |
| Invalidate / 失效通知 | 告诉宿主旧画面需要重新计算，常通过 $.ui.invalidate 发出 | 5.4 |
| Reactive state / 响应式状态 | 记录 UI 读取了哪些状态，状态更新后重绘依赖它的界面 | 5.4 |
| State 与 store | 前者主要是会话状态，后者是插件持久键值空间；寿命和并发语义不同 | 5.4 |
| Atom | 当前状态接口中的一个可读取、更新的状态单元，具体方法需查目标版本 | 5.4.2 |
| Atomic / 原子 | 一个操作不会被其他参与者看见中间状态；单次写入不等于读改写整体原子 | 5.4.1 |
| Transaction / 事务 | 把多步操作作为整体处理；store 的 get→修改→set 不能直接当作事务 | 5.4.1 |
| Hot reload / 热重载 | 开发时重新加载修改后的模块；旧实例的变量和回调需要分别处理 | 5.5 |
| Generation / 代次 | 区分当前任务与旧任务的编号，结果回来后用它检查是否仍有效 | 5.5 |
| Stamp / 版本标记 | diff 把代次与比较基准组合成的标记，用于丢弃过时读取结果 | 6.7.1 |
| Model / 数据模型 | diff 案例中指用于绘制的数据结构，不是语言模型 | 6.7.1 |
| Exactly-once | 操作效果恰好发生一次；报告只说明文档列出的特定恢复保证 | 5.5 |

| Teaching model / 教学模型 | 研究者写的简化执行器，用于检查解释与语言语义，不是宿主源码 | 8.2.2 |
