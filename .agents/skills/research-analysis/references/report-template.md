# 分析判断的输入、证据与报告结构

按问题裁剪报告，分别组织任务输入、可核查依据和本次判断。正文的章节不必逐一对应 fields.json 中的证据字段。

## 任务输入与来源登记

| 内容 | 记录位置与处理 |
| --- | --- |
| 分析问题、场景、硬约束、判断标准及优先级 | 写入 outline.goal／time_range 或相关字段描述；notes.md 保留用户原文、归属和解释，正文简要交代采用条件 |
| 贡献者观点、偏好、经验与待检验假设 | 在 notes.md 归属到实际提供者及场景，正文区分偏好、假设和事实声明；未提供时不编造 |
| 已有报告及采用范围 | sources 或 light 的 assessment.sources 登记实际版本、读取日期、定位与必要散列；正文引用来源 |

任务目标和用户指定偏好是分析条件，不作为等待外部证据确认的字段，不因没有 URL 而标 unknown／not_applicable，也不为它们编造来源。贡献者声称的性能、成本或实际效果属于可检验事实；影响结论时仍需证据，未核实时不能当作已确认前提。

未提供个人观点时可依据已有成果开展明确标注为“本次分析”的推导，不为填表要求贡献者补出立场。真正会改变结论的缺失约束或标准，按条件分支说明或针对性澄清。

影响判断的约束、优先级或关键假设必须进入 goal／time_range 或字段描述，以绑定现有范围指纹；notes.md 不能单独承担这一作用。输入实质变化时按受影响范围复核结果，不只改笔记或报告措辞。

## 证据字段

只把需要核查或论证的主张放入 full 的 fields。最小分析可只有 judgment 一个核心字段，reason 说明推导及条件，evidence 只关联实际支持推导的来源事实；用户偏好不需要伪装成外部事实证据。

| 可选字段 id | 何时单独设置 |
| --- | --- |
| facts | 有必要单独核查、且直接影响判断的事实主张 |
| judgment | 要回答的主要问题及有条件结论，通常为核心，推导类结果用 inferred |
| alternatives | 替代解释或方案比较本身是本轮独立问题 |
| limitations | 限制或证据缺口本身需要单独回答；其余可写入判断的条件与理由 |

字段核心性由用户目标决定，不按章节数自动建立字段。confirmed 需直接证据，inferred 需真实依据及推导理由，unknown 用于未能回答的事实／判断问题；不能为填写输入信息制造证据字段。事实冲突按公共证据规范处理，偏好不同或未获支持的个人假设不自动构成事实证据冲突。

light 仍在 notes.md 与 assessment 中记录实质分析、实际来源和缺口，不为使用本模板强制升级为 full；复杂论证、逐字段续查或实质来源冲突再按公共规则选择 full。

## 正文组织

简短分析可依次写问题与判断标准、主要判断、关键依据及推导、条件与缺口。复杂分析再展开贡献者观点、替代方案、反例、取舍、置信理由和后续验证。

结论附近引用采用报告和决定性的原始来源，说明版本、适用条件及采用范围。分别解释证据质量、关键假设状态和判断对条件变化的敏感性；不把分析完成度当作观点已经被实验验证。
