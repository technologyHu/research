# 分析洞察的输入、证据与报告结构

围绕主题或问题选择相关调研输出，形成分析／洞察报告。正文章节与证据字段分别组织，已有取舍类报告及其 judgment 字段继续有效。

## 任务输入与来源登记

| 内容 | 记录位置与处理 |
| --- | --- |
| 主题／问题、关注点、样本选择、时间及覆盖边界 | 写入 outline.goal／time_range 或字段描述；notes.md 保存输入原文及说明 |
| 贡献者观点、经验、偏好与待检验假设（可选） | 记录实际归属，区分观点、假设和事实声明；未提供时直接开展标为“本次分析”的综合，不要求补出立场 |
| 采用报告及相关主张 | sources 或 light 的 assessment.sources 登记真实版本、日期、定位和必要散列，正文给出引用 |

任务目标和用户给定条件属于分析输入，不因没有 URL 标 unknown／not_applicable，也不编造外部来源。贡献者提出的性能、成本等现实事实若影响结论，仍需核查。影响分析的范围、假设或约束须进入 goal／time_range 或字段描述，使范围指纹覆盖其含义；notes.md 不能单独承担这一作用。

硬约束、偏好排序与方案反转条件用于选型问题。主题综合、机制解释等分析只需明确相应关注点与范围，不机械填选型表。

## 证据字段

新 full 任务可从一个 insight 核心字段开始，使用 inferred、reason 和真实 evidence 记录归纳与推导。字段核心性由本轮目标决定；根据问题需要扩展，不按章节数创建字段。

| 可选字段 id | 何时使用 |
| --- | --- |
| facts | 必须单独核查且影响分析的事实主张 |
| synthesis | 综合、对照结果本身是独立分析问题 |
| insight | 核心模式、关联、机制解释、启示或其他分析发现，通常为核心 |
| alternatives | 替代解释、争议或方案比较是独立问题 |
| opportunities | 研究缺口或机会是独立问题，说明推导及验证方式 |
| judgment | 实际需要方案取舍或建议，亦用于兼容既有任务 |
| limitations | 限制或证据缺口需要独立回答；其余写入相应发现的边界与理由 |

confirmed 要有直接证据；inferred 要有实际依据及分析理由；unknown 用于未能回答的事实／分析问题。不能用空洞的新颖性表述代替推导，来源作者的推断不能经转述升级为事实。light 沿用 notes.md 与 assessment，不为使用该模板强制升级为 full。

## 正文组织

默认按以下部分裁剪：主题与范围、核心发现、依据与分析、适用边界、未解决问题。

按目标扩展模式／关联、机制解释、争议、演进、机会或应用建议。每项重要洞察应让读者看出依据来自哪里、经过怎样的分析、带来什么理解及在什么范围成立。分析本身可以是交付，不要求每篇报告都有新颖洞察、排名或行动建议。

引用版本与阅读日期保持真实。只基于有限样本时，结论覆盖这些样本；讨论更广范围或趋势须有相应证据和时间口径。报告完成度、分析价值与单项主张的置信程度分别判断。
