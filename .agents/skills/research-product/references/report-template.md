# 产品报告结构

围绕用户需要解决的任务组织内容。公开技术信息不足时清楚说明，不能用常见架构填补闭源细节。

涉及选题、权威性／影响力或公司与投资背景时，按 [产品评估标准](selection-criteria.md) 展开 identity／evidence／assessment，说明运营主体、领域团队、适用的融资或母公司支持、真实客户关系及对判断的作用。按实际产品形态裁剪，产品采用数据不直接使用母公司总体规模。

| 默认字段 id | 章节／问题 |
| --- | --- |
| identity | 产品、提供方、版本／套餐、发布日期、资料日期、目标用户与定位 |
| workflow | 典型任务、输入、主要操作、输出、人机协作与失败恢复 |
| capabilities | 主要能力、限制、权限、支持平台和集成边界 |
| mechanism | 有公开证据的关键技术机制，事实与推断分别陈述 |
| access_cost | 访问条件、部署、套餐／配额与成本；仅在研究目标相关时调查 |
| evidence | 官方案例、实际体验、独立评价；区分宣传、演示和实测 |
| alternatives | 与相关替代方案在统一目标下的差异 |
| assessment | 适用场景、风险、采用条件和仍需验证的问题 |

对比时明确每个产品的版本、地区、套餐、日期和使用条件。优先比较任务完成路径与能力边界，不能把营销名称等同于实现机制。
