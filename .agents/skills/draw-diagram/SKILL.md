# 技术绘图入口

先判断图的解释价值和交付形式。来源明确且适用的已有图可直接插入报告，按 [已有图复用](../research-common/references/writing-policy.md#已有图复用) 核对并标注，无需启动生成后端。需要新绘且满足下述能力条件时，报告中的简单示意优先采用 Markdown 可渲染代码图；需要静态技术图时再选择绘图技能。独立静态绘图默认 SVG＋PNG，用户指定技能、源文件或其他格式时以用户要求为准。

用于受管报告配图时，沿用 [配图选型](../research-common/references/writing-policy.md#图表与代码) 和 [交付规则](../research-common/references/delivery-policy.md#自绘图的保存)：调用方负责必要性、事实依据和报告验收，本入口负责形式与后端选择、生成及绘图检查。内联图不强制导出静态文件；需要文件时按实际嵌入或用户要求交付。必要时可使用图片生成服务表达代码图难以清楚呈现的内容，不将成本偏好变成禁止生成图片。不另建调研任务或正式报告，不回调顶层入口。

## 图像能力条件

先遵守本项目的 [图片使用与生成](../../../AGENTS.md#图片使用与生成) 约束，确认当前模型能实际接收并理解图片；不能仅凭图片查看、截图或渲染工具存在就认定模型具备该能力。无此能力或无法确认时，只复用用户提供、已有报告或原始来源中的现有图片，可下载、复制和引用原图，不生成、重绘或修改图片，也不通过 SVG／HTML 代码、Mermaid 渲染、格式转换、截图或委派其他技能、代理、外部模型和服务绕过限制。

此时不进入下述生成、导出和修图流程，也不要求凑齐 SVG＋PNG。依据原文图注、上下文与版本判断已有图是否适用，能做文件及链接检查但不能宣称已目视复核；没有合适图片时用文字或表格，明确要求的新图无法交付时说明限制。

## 路由优先级

依次判断，前一项优先于后一项：

1. **用户指定**：遵循明确指定的技能、源格式和输出要求；后端不支持时说明限制，不静默替换。不把导入支持误当成导出支持。
2. **已有图**：有助于理解且来源、版本、清晰度适用时直接复用，插入正文并注明来源，不要求先重绘、转为代码图或统一风格。确需修改时沿用原后端、源文件与风格；只有用户要求切换，或原后端不能满足新需求时才换，并说明原因。
3. **报告内联图**：没有静态格式要求时，流程、时序、状态、概念及简单架构优先直接编写目标阅读器支持的 Mermaid 等代码图，完成语法、渲染及视觉检查后写入 Markdown，不启动静态后端或强制生成图片。复杂关系、精确布局或兼容性需要静态文件时，直接进入下一项；不能为省成本牺牲清晰度或原貌证据。
4. **静态图表达目的**：解释系统运行、连接关系和事件过程用 Fireworks；比较方案、解释概念和组织规划信息用 diagram-design。目的优先于题材关键词，例如“比较三种微服务架构”用 diagram-design。
5. **静态图型默认**：目的仍不明确时，按下表选择；独立静态“画流程图”默认 Fireworks，不为常规选型停下来询问。

## 默认风格

用户要求、项目已有品牌与所修改图的风格优先；没有这些约定时，使用浅色不透明底、清晰深色文字、少量强调色和本地已安装的中文字体，沿用资料语言。普通工程图优先选择清爽浅色样式；明确要求 C4、云部署等图型时保留后端对应的工程表达。

把这些选择作为本次既定偏好传给后端，包括 diagram-design 的首次风格选择，不重复询问是否采用默认；不为此创建品牌配置或改写上游样式文件。同批图协调背景、字体和主色即可，无须强制像素级一致。

需要 PNG 时默认宽度为 1920px，用户尺寸或用途要求优先；同时输出 SVG 和 PNG 时保留一致的图内背景，diagram-design 导出时也在 SVG 内绘制底色。明确要求透明背景时才去掉它。内联图沿用阅读器主题，不要求固定像素画布；均以实际显示尺寸检查中文和小字可读性。

## 执行

1. 简短说明图要解释的问题、形式与依据。内联图直接编写，静态图再读取所选技能的 `SKILL.md` 和本图需要的参考文件；路径及脚本从所选技能目录定位，避免误用全局旧安装。
2. 内联图完成代码与渲染检查；静态图按所选技能完成生成、适用检查、所需格式导出与视觉复核。**一张图只用一个后端**，同一报告的不同图可按需选用不同形式与后端。
3. 按上述偏好保持同批图协调，不跨后端转换图模型、叠加校验器或重新实现样式系统。

### Fireworks 分支

按 [Fireworks 指令](../fireworks-tech-graph/SKILL.md)选择匹配的图型与样式，生成 SVG，完成适用检查；需要 PNG 时再导出。独立静态绘图沿用 SVG＋PNG 默认，报告则只保留实际需要的格式。默认不调用其交互 HTML 或动画输出。

### diagram-design 分支

按 [diagram-design 指令](../diagram-design/SKILL.md)完成设计与检查。它可以在内部生成静态 HTML，随后按 [静态导出流程](../diagram-design/references/export.md)输出任务所需的 SVG／PNG；独立静态绘图默认两者都有，不把内部 HTML 当作报告可嵌入图片交付。

默认采用该技能的系统字体选项；用户指定品牌字体时，按其要求与实际离线条件处理，不以默认值覆盖明确偏好。图中必须保留的标题、图例与说明放在 SVG 内，避免只写在 HTML 外层而在导出时丢失。默认不添加交互控件或动画。

## 文件保存

- 内联代码图直接保存在 Markdown 中，不应用下列静态图文件命名和源文件要求；检查预览仍放在当前任务临时目录。
- 用户指定目录、文件名及项目已有产物规则优先。没有约定时，放在当前工作目录的 `diagrams/<主题>/` 下。
- 同图文件使用同一主文件名，并用后端名标识来源，例如 `rag-architecture.fireworks.svg`、`.png`、`.json`，或 `rag-comparison.diagram-design.svg`、`.png`、`.html`。用户已指定其他名称时保留，在 SVG 注释中记录所用后端和源文件相对路径即可。
- 保留实际生成源：Fireworks 的 JSON（直接绘制 SVG 时以 SVG 为源），或 diagram-design 的内部 HTML。项目要求工作资料另存时遵循该规则；源文件和检查记录不作为默认交付物，也不自动删除。
- 修改图时更新对应源与 SVG、PNG；新图重名时加可读后缀，避免覆盖其他图。不新增清单或配置文件。

## 交付与例子

内联图保存在报告中，说明图注、依据、已完成的渲染检查及阅读器兼容性；不额外交付检查截图。静态图提供实际要求格式的链接，并说明后端、检查和限制。必需输出或检查未完成时如实说明，不把未完成的输出称为已完成。

例如一份 RAG 报告中的配图：

- 系统架构、检索调用时序：Fireworks。
- 三种检索方案对比、技术演进时间线：diagram-design。

显式调用示例：`$draw-diagram 画一张 RAG 系统架构图，输出静态 SVG 和 PNG。`
