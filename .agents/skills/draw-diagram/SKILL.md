# 静态绘图入口

满足下述图像能力条件时，按每张图要表达的内容选择同目录下的一个绘图技能，默认交付静态 SVG＋PNG；用户指定技能、源文件或其他格式时，以用户要求为准。

用于受管报告配图时，沿用当前任务的 [配图要求](../research-common/references/writing-policy.md#自绘技术图) 和 [交付规则](../research-common/references/delivery-policy.md#自绘图的保存)：调用方负责配图必要性、事实依据和报告验收，本入口负责后端选择、生成与绘图检查。默认生成 SVG＋PNG；最终交付格式、目录、源文件保留和清理由当前调用方与任务配置确定，不另建调研任务或正式报告，不回调顶层入口。

## 图像能力条件

先遵守本项目的 [图片使用与生成](../../../AGENTS.md#图片使用与生成) 约束，确认当前模型能实际接收并理解图片；不能仅凭图片查看、截图或渲染工具存在就认定模型具备该能力。无此能力或无法确认时，只复用用户提供、已有报告或原始来源中的现有图片，可下载、复制和引用原图，不生成、重绘或修改图片，也不通过 SVG／HTML 代码、Mermaid 渲染、格式转换、截图或委派其他技能、代理、外部模型和服务绕过限制。

此时不进入下述生成、导出和修图流程，也不要求凑齐 SVG＋PNG。依据原文图注、上下文与版本判断已有图是否适用，能做文件及链接检查但不能宣称已目视复核；没有合适图片时用文字或表格，明确要求的新图无法交付时说明限制。

## 路由优先级

依次判断，前一项优先于后一项：

1. **用户指定**：遵循明确指定的技能、源格式和输出要求；后端不支持时说明限制，不静默替换。不把导入支持误当成导出支持。
2. **已有图**：修改时沿用原后端、源文件与风格；只有用户要求切换，或原后端不能满足新需求时才换，并说明原因。
3. **表达目的**：解释系统运行、连接关系和事件过程用 Fireworks；比较方案、解释概念和组织规划信息用 diagram-design。目的优先于题材关键词，例如“比较三种微服务架构”用 diagram-design。
4. **图型默认**：目的仍不明确时，按下表选择；无其他语境的“画流程图”默认 Fireworks，不为常规选型停下来询问。

| 图的主要内容 | 使用技能 |
| --- | --- |
| 系统架构、微服务、C4、云部署、网络拓扑 | [fireworks-tech-graph](../fireworks-tech-graph/SKILL.md) |

## 默认风格

用户要求、项目已有品牌与所修改图的风格优先；没有这些约定时，使用浅色不透明底、清晰深色文字、少量强调色和本地已安装的中文字体，沿用资料语言。普通工程图优先选择清爽浅色样式；明确要求 C4、云部署等图型时保留后端对应的工程表达。

把这些选择作为本次既定偏好传给后端，包括 diagram-design 的首次风格选择，不重复询问是否采用默认；不为此创建品牌配置或改写上游样式文件。同批图协调背景、字体和主色即可，无须强制像素级一致。

默认 PNG 宽度为 1920px，用户尺寸或用途要求优先；两种输出保留一致的图内背景，diagram-design 导出时也在 SVG 内绘制底色。明确要求透明背景时才去掉它。以实际显示尺寸检查中文和小字可读性，不只看导出像素数。

## 执行

1. 简短说明每张图的类型与所选技能，然后读取该技能的 `SKILL.md` 和本图需要的参考文件。路径相对于本入口目录解析；脚本也从所选技能目录定位，避免误用全局旧安装。
2. 按所选技能完成整张图，包括生成、适用的检查、静态导出与视觉复核。**一张图只用一个后端**；同一报告的不同图可以分别使用两者。
3. 按上述偏好保持同批图协调，不跨后端转换图模型、叠加校验器或重新实现样式系统。

### Fireworks 分支

按 [Fireworks 指令](../fireworks-tech-graph/SKILL.md)选择匹配的图型与样式，生成 SVG，完成适用检查并导出 PNG。默认不调用其交互 HTML 或动画输出。

### diagram-design 分支

按 [diagram-design 指令](../diagram-design/SKILL.md)完成设计与检查。它可以在内部生成静态 HTML，但本入口默认需要的最终文件仍是 SVG＋PNG，继续执行其 [静态导出流程](../diagram-design/references/export.md)，不要只交付 HTML。

默认采用该技能的系统字体选项；用户指定品牌字体时，按其要求与实际离线条件处理，不以默认值覆盖明确偏好。图中必须保留的标题、图例与说明放在 SVG 内，避免只写在 HTML 外层而在导出时丢失。默认不添加交互控件或动画。

## 文件保存

- 用户指定目录、文件名及项目已有产物规则优先。没有约定时，放在当前工作目录的 `diagrams/<主题>/` 下。
- 同图文件使用同一主文件名，并用后端名标识来源，例如 `rag-architecture.fireworks.svg`、`.png`、`.json`，或 `rag-comparison.diagram-design.svg`、`.png`、`.html`。用户已指定其他名称时保留，在 SVG 注释中记录所用后端和源文件相对路径即可。
- 保留实际生成源：Fireworks 的 JSON（直接绘制 SVG 时以 SVG 为源），或 diagram-design 的内部 HTML。项目要求工作资料另存时遵循该规则；源文件和检查记录不作为默认交付物，也不自动删除。
- 修改图时更新对应源与 SVG、PNG；新图重名时加可读后缀，避免覆盖其他图。不新增清单或配置文件。

## 交付与例子

提供实际生成的静态 SVG 与 PNG 链接，并简短说明使用的后端、已完成的检查和仍有的限制。检查没有运行或 PNG 没有导出成功时如实说明，继续处理可修复问题，不把未完成的输出称为已完成。

例如一份 RAG 报告中的配图：

- 系统架构、检索调用时序：Fireworks。
- 三种检索方案对比、技术演进时间线：diagram-design。

显式调用示例：`$draw-diagram 画一张 RAG 系统架构图，输出静态 SVG 和 PNG。`
