# 提交前规范检查与轻量校验

每篇普通提交或 amend 都检查实际候选版本。目标是确认本次交付符合仓库规范、文件齐全且提交归属正确；默认读取现有本地资料，不访问来源网站、重跑实验或重新评审整篇论证。

## 读取规则与确定版本

先读取目标仓库的 AGENTS.md、[共用交付规范](../../research-common/references/delivery-policy.md) 和必要的 [主题注册表规则](../../research-common/references/theme-registry.md)。本文是检查清单，目录命名与清理授权的详细要求仍以共用规范及用户当前要求为准。

按 [候选树检查](git-workflow.md#候选树检查) 记录实际 base、candidate-tree、版本来源、报告主文件及精确变更清单。暂存模式只检查所选暂存版本；工作区另有未提交新版本时，不把它的资料当作候选缺失文件，也不因提交旧版本而清理它。

普通提交比较起始 HEAD；amend 核对相对原 HEAD 父提交的最终范围，并与原 HEAD 比较本轮新增修订。根提交使用空树，不假定存在 HEAD^。所有本地文件检查从候选 tree 导出的隔离快照执行，读取代码使用当前可信技能安装，不能执行候选中的脚本或钩子。

## 每篇必检清单

| 检查项 | 检查方法与通过条件 |
| --- | --- |
| 一份报告一个 commit | 按报告稳定 ID、主文件与实际交付范围认领变更，一笔只有一份独立报告及必要附件。比较报告和本篇补充文档仍算一篇；另一份独立报告、共享工具或公共维护修改另分组。不能把不同目录的同 ID 直接视为同一篇；先排除身份碰撞。 |
| 目录与类型 | 核对两类成果根、实际对象类型、主文件及附件位置。分析主题保持单层目录，多级主题由注册表推导；计划使用自己的位置。新报告按现行规则保存，基线已有的旧布局按兼容规则检查；不为提交自动迁移。 |
| 名称与主题 | 核对规范主题 ID、各级 slug、专题片段、日期时间和 survey／compare 前缀；主题注册表读取候选版本，不能借用工作区未入库的主题。复用 [目录工具](../../research-common/scripts/research_catalog.py) 的解析与生成规则，不另写一套正则；旧分隔符和明确声明的中文正式名称按共用例外处理，不从标题猜类型或新建主题。 |
| 身份与修订 | 核对 `report_id`、分类、`created_at`、`updated_at` 与路径一致。新格式的 Markdown 与同名 `.meta.json` 都须在候选树中，旧格式可读取内嵌元数据。改名时同步这对文件及引用，保留报告 ID 和创建时间。无稳定元数据的旧报告结合基线认领，多个交付共用同一 ID 时阻塞。 |
| 临时文件与清理状态 | 核对本轮已结束任务的临时目录是否已清理，或是否有用户明确保留要求；不能把 Git 忽略当成已清理。候选变化中不能新增／修改未登记的临时产物、缓存、IDE 配置、工作源码副本和原始结果。已有临时产物的删除可以提交。其他任务、持续维护资料及用户保留文件不属于本次清理范围。 |
| 正文、引用与附件 | 主报告、引用文章、实际嵌入的图片和已登记额外交付在候选中存在；本地链接可解析，不指向 .tmp、个人绝对路径或未入库文件。共享资源须已在本笔基线中，或随当前报告获准提交；仅出现在未来另一笔候选中不能算可用。 |
| 差异与授权 | 精确文件／片段均获准，无冲突标记及 Git 差异检查错误，不带入无关暂存或未暂存内容。已有无关暂存项通过隔离候选保留，不为凑单篇清空索引。 |
| 状态与缺口 | 报告状态、版本与提交说明相符，partial 的实际缺口保留。受阻、证据失效或文件缺失时不能写成完整交付；仅通过静态检查不能宣称研究一致性或事实准确性已验证。 |

整篇报告删除时，从 base 识别原交付单元，核对候选中存活的引用已处理；不对已删除目录运行需要主文件存在的检查，也不为通过校验重建报告。纯计划或公共维护提交另按其范围检查，不强制凑入一份报告。

## 轻量检查的执行

```text
git --literal-pathspecs diff-tree --no-commit-id --name-status -r -z <base> <candidate-tree>
git diff --check <base> <candidate-tree>
python -B <skills_root>/research-common/scripts/validate_report.py <snapshot-report-dir>
```

参数使用实际解析出的提交、tree 和隔离目录，不能照抄尖括号。第一条读取精确清单，不按换行或空格拆文件名；默认 report.md 可以直接运行第三条。自定义主文件、登记附件与跨报告引用按真实交付配置补充静态检查，不伪造 outline 让默认命令放行。`consistency_checked: false` 表示仅完成文件检查，不作为任务 verify 的替代品。

当前真实任务的证据、版本、范围或完成状态受影响，或清理需要的回执不存在／失效时，再执行共用工具的 `verify --work-dir <actual-work-dir>`。回执是否仍有效须核对当前内容；工作区的 verify 不能证明另一个候选版本通过。旧任务已清理时按保存记录检查并报告限制，不为提交重建研究流程。

## 清理与阻塞处理

对本轮已结束且应清理的任务，沿用 [保存与清理规则](../../research-common/references/delivery-policy.md#最终检查与清理)。需要时运行 `cleanup-plan --work-dir <actual-work-dir>`，检查真实回执、精确目录和清单；它只预览，不执行删除，也不是授权凭据。

已有覆盖该范围的有效授权时直接执行清理并复查，无需重复确认。缺少授权时先完成其余可执行检查，再一次列出待清理精确范围、保留项和实际阻塞；取得授权后只处理该范围。用户明确保留时登记原因，不能把未知目录或其他任务当作垃圾删除。工作区命名锁正被占用时等待，不把锁当作可清理任务。

对每篇形成简短结果：报告与候选 tree、单篇归属、目录／命名／身份、文件与引用、临时资料已清理／明确保留／待处理、实际验证层次及剩余问题。应清理但未清理且无保留要求、候选混篇、身份冲突或文件检查失败时，暂不提交该篇；其他独立且已通过的报告可继续。用户明确例外须记录，不能把例外改写为通用规则。

清理或修复改变报告内容、候选范围、选定文件或 HEAD 后，重新核对受影响项和实际候选；仅清理未入库临时文件也要确认正式报告仍保留。检查通过后才执行提交，提交后继续核对实际 tree 与预期一致。
