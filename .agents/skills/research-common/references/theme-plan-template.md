## 按类型填写示例

下列均为假设场景。先核对 [计划纳入条件](theme-planning.md#计划纳入条件)，生成 `plan.md` 时只复制上方题头、标题和两张表。用常用词和短句，必要的术语或缩写首次出现时简要解释。按 [各类型的评估标准](theme-planning.md#权威性影响力与优先级) 写关键证据和排序理由，附来源、版本或位置及核对日期。优先级只填级别。

| 对象类型 | 类型评估与证据 | 优先级 |
| --- | --- | --- |
| 论文（paper） | 可信度为中，方法和实验可核对，在其他数据集上的表现待验证。影响力为中，已有独立研究采用。先核对实验条件，判断能否作为本轮对照。 | P1 |
| 开源项目（open-source） | 工程可信度为中，指定版本有代码和测试，实际运行情况待验证。生态影响待核实，未查到其他团队在正式环境使用的证据。后续复现前，须先核对接口和出错时的行为。 | P0 |
| 产品（product） | 运营方有行业交付记录。能力可信度为中，独立反馈只涉及试点。市场影响待核实，厂商只公布了注册人数。先验证影响产品选择的主要功能，再查适用条件。 | P2 |
| 评测（benchmark） | 测量可信度待核实，目前只有发布说明和样题。待查数据怎样分组、如何评分、对照方法用了多少资源。影响力待核实，只看到维护方的结果。先核对评测规则，再排序。 | 待定 |
| 分析洞察（analysis） | 两份报告的原始记录可相互核对，样本有限。比较部署条件并检查反例，帮助判断哪种部署方式更合适。 | P1 |
