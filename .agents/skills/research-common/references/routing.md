# 内部类型与成果复用

下表说明共用工具接受的内部类型，不负责选择或调用顶层入口。对象调研保存到 research-reports，分析洞察保存到 analysis-reports。模式区分单对象和同类型比较，theme 是问题归属；`--topic`／outline.topic 仍是标题字段。

先按用户目标确定本轮工作性质，再开展资料获取和背景核查。仅需函数解释、源码导览或调用链追踪时，直接使用 [code-understanding](../../code-understanding/SKILL.md)；需要完整调研或已有受管任务时，按下表选择类型。

| type | 目标 | 类型技能 |
| --- | --- | --- |
| `paper` | 精读或比较论文，包括 survey 论文 | [research-paper](../../research-paper/SKILL.md) |
| `open-source` | 分析公开项目的架构、源码和工程机制 | [research-open-source](../../research-open-source/SKILL.md) |
| `product` | 理解产品能力、使用流程、公开机制与约束 | [research-product](../../research-product/SKILL.md) |
| `benchmark` | 理解评测任务、数据、指标、协议及可比性 | [research-benchmark](../../research-benchmark/SKILL.md) |
| `analysis` | 基于已有调研输出，对主题或问题综合分析，提炼模式、关联、机制解释或其他洞察；贡献者思考可选 | 按调用方的分析目标与 [分析质量标准](analysis-criteria.md) 执行 |

## 已有成果核对与复用

先定位用户指定的资料、相关主题当前计划的成果索引与实际报告，计划位置按 [交付规范](delivery-policy.md#主题计划的保存与收口) 区分两个入口，再按需要寻找尚在的受管任务。只阅读与本轮问题有关的成果，核对实际版本／时间、覆盖的主张、适用条件和重要缺口。目录、完成标记或文件存在不能单独证明可复用。

| 核对结果 | 本轮处理 |
| --- | --- |
| 已有成果回答当前问题且符合版本与场景 | 复用并记录实际采用范围；直接回答即可的请求不另建任务或重复报告 |
| 只有部分主张可用，或版本／条件变化影响部分内容 | 保留有效部分，仅为缺失或失效问题补查，说明原版本、日期和限制 |
| 没有可用成果 | 按实际对象类型建立所需基础任务，不把未知内容写成既有结论 |
| 已有成果可用，用户需要主题综合、问题解释或分析洞察 | 采用相关报告与可选观点进入 analysis，不因新的分析目标重跑全部来源对象调研 |

对象调研复用既有结构化证据及原始来源，仍按当前问题核对有效性；只有旧报告而无原记录时，按本轮范围回查所需证据，不把报告摘要直接升级为 confirmed。analysis 按其来源登记规则采用已有报告，保留来源推断与缺口。复用不改变原访问日期，也不免除用户明确指定的版本、文章获取或刷新要求。

## 执行交接与基础补查

- `paper`、`open-source`、`product`、`benchmark` 的对象调研／缺口补查可由 research-deep 执行；`analysis` 的综合与推导由当前调用方执行。证据齐备后可使用 research-report 成稿、校验与回写，不调用顶层入口。
- 跨类型对象调研先核对各类型已有成果，仅对缺口建立／恢复任务。超出当前目标的主题综合或洞察保留为后续事项，不自动切换工作流；已有成果足够时不重复生成基础报告。
- analysis 发现基础事实缺口时，交接须说明待核实问题、实际对象类型／版本、已有依据及缺失部分、接受条件、结果应返回的分析任务和受影响发现。当前授权内做针对性补查，结果回到原分析，不重新规划同一分析或扩大为全量调研。
- 用户限定只使用现有资料时，保留缺口并形成有边界的条件性／部分分析；超出本轮范围的补查记录为后续任务，不以补查为由自行扩大任务。
- 背景与优先级在选型后按需核查：对象调研使用其类型标准；analysis 检查依据、解释目标、样本与假设，观点归属按实际输入记录。机构、融资等仅在影响本轮分析时补查，详见 [对象背景](object-background.md) 和 [主题计划维护](theme-planning.md#权威性影响力与优先级)。

## 决策方法

- survey 是论文的一种，使用 paper；单篇报告目录为 `survey-<专题标识>__<时间>`，专题标识可采用论文简称或体现阅读范围。分析分类体系、检索与选择边界、代表工作覆盖、综合结论和局限，不套用必须有原创算法或实验的结构。
- 公开项目的源码／工程机制用 open-source；闭源产品能力用 product。产品附带论文或 SDK 不自动改变研究对象。
- 基于已有调研解释主题或问题时，按当前分析目标执行，无需预设观点或选型目标；纯计划任务只维护对应计划。基础对象材料不足时按实际缺口补查，结果返回调用方，不切换顶层工作流。
- 跨类型来源按前述复用与补查规则处理，不把混合来源对象作为 analysis items 或自动分类兜底。
- analysis 的 items 表示待分析主题／问题；一个主题的多个维度可放在 fields，采用报告作为来源保留原类型。使用多份报告不自动转为 comparison，单篇 survey 精读仍归 paper。
- 某技术方向中的参考文献只在需要单独精读或比较时成为论文调研对象，不为每个链接创建报告。
- 无需澄清的小范围边界可说明假设后执行；目标差异会显著改变产出时再询问。

## 模式与深度

- `single`：一个明确对象或分析主题／问题。
- `comparison`：至少两个同类型对象或需要实际比较的分析主题／问题，保留共同目标与可比口径。
- `brief`：核心问题、依据与边界；`standard`：主要维度；`detailed`：进一步展开机制、实验、协议或论证。深度不是填满模板的要求。
